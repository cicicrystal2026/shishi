# 拾史桌面端技术架构说明

版本 v1.0　产品基线 shishi-desktop-v1.0　阶段 设计基线

## 1 架构结论

首版采用模块化单体加独立后台 Worker：桌面浏览器运行界面，后端统一管理项目、来源、审批、费用和文件访问，Worker 异步执行识读、模型调用与成片渲染。SQLite 保存初期单机数据，文件存储保存书页和媒体。暂不引入微服务、分布式队列集群、向量库或多 Agent 常驻网络。

架构图中的 T01–T10 是逻辑模块，不代表十个部署服务。PRD 既定的两次内容判断保留：故事确认、成片审阅；模型选择和分镜制作在后台进行。具体模型、SDK、OCR 和声音服务在接入时验证，图片与视频工具不能由文字模型能力推断。

图源为 architecture.json，使用 tools/render_architecture.py 生成同版本 SVG、PNG 和 Mermaid。默认能力图是设计，不表明任何接口或产品已经开发上线。

## 2 技术栈与部署边界

| 层 | 首版建议 | 边界 |
| --- | --- | --- |
| 界面 | React 加 TypeScript | 桌面 Web，1280px 起；复用当前原型的信息架构 |
| API 与编排 | Node.js 加 TypeScript | 统一鉴权、校验、状态与工具入口；框架在实现时锁定 |
| 工作执行 | 独立 Worker 进程 | 网络任务与渲染不占用 API 请求；初始一个调度实例 |
| 持久化 | 单机 SQLite | 事务保存版本、任务和预算；不在网络盘跨机器共享数据库 |
| 队列 | SQLite Job 表加租约 | 小规模持久队列；短事务抢占，不持有跨网络调用事务 |
| 文件 | 本地受控目录加 Storage 接口 | 后续可换对象存储；客户端通过受控 API 获取文件 |
| AI | OpenAI 默认文字与图片适配器 | 显式能力列表与配置快照，不硬编码最新模型 |
| 声音 | TTS 适配器 | 以实际音频时码驱动镜头与字幕 |
| 剪辑 | 时间线 JSON 加 FFmpeg | 先图片运动、字幕和混音，视频片段可选接入 |
| 运行环境 | 单台主机，本机或私有服务器 | 本机服务退出则任务停止，重启恢复；离开浏览器页面不停止服务 |

推荐依据是减少个人运营维护成本。React、SQLite 与 FFmpeg 的功能依据见文末官方来源；这些组件没有在本轮安装或接入。若未来需要多实例 Worker、高写并发、跨主机部署或 SaaS，再迁移数据库与队列，保持项目和任务接口不变。

本机模式仅监听回环地址且使用会话保护；远程模式必须 HTTPS、登录会话和私有存储。V1 单用户不意味着接口可以无鉴权暴露到公网。首版不创建收费和多人权限体系。

## 3 逻辑模块职责

| 模块 | 职责 | 主要实体 |
| --- | --- | --- |
| T01 桌面界面 | P01–P08、弹窗、表单、进度、预览和反馈 | 项目视图、页面状态 |
| T02 项目 API | 鉴权、输入校验、偏好版本、项目快照和审批 | Project、PreferenceVersion、Approval |
| T03 工作流编排 | 阶段依赖、暂停恢复、局部重做和可接受替代路径 | WorkflowRun、Dependency、ChangePlan |
| T04 Agent 与 Skill | 加载阶段方法、结构化输出、创作和质检 | SkillVersion、PromptVersion、StageResult |
| T05 能力网关 | 文字、图片、识读、声音与视频的工具适配和结果校验 | ProviderConfig、ModelConfig、Capability |
| T06 来源与版本 | 原页坐标、事实、引用、修订差异和内容审批状态 | SourcePage、SourceSpan、Claim、ScriptVersion |
| T07 任务与预算 | 幂等、租约、服务商状态、预留额度和费用核实 | Job、JobAttempt、BudgetLedger、ProviderEvent |
| T08 素材存储 | 原文件、候选、选中、外部导入、访问与保留 | Asset、AssetVersion、StorageKey |
| T09 时间线渲染 | 真实配音时码、镜头编排、字幕、混音与渲染校验 | Shot、TimelineVersion、RenderJob |
| T10 修改与交付 | 自然语言意见映射、版本比较、导出包和来源清单 | Feedback、ChangePlan、Export |

T10 生成修改计划，T03 判断依赖，T07 检查成本后执行，避免用户意见直接触发无限媒体重生成。审批绑定内容版本，费用授权绑定预算规则与任务批次，二者不是同一个状态字段。

## 4 端到端执行过程

1. 用户创建作品，后端冻结默认偏好版本、本条覆盖及能力配置；输入文件先校验再进入识读，页码不清时使用图片序号，不伪造来源。
2. Agent 用资料整理 Skill 输出 SourceSpan 和 Claim，再生成带引用的剧本；结构检查与来源存在性检查通过后进入故事确认。关键疑点无法补证时阻塞相关结论。
3. 确认请求携带项目 ID、剧本版本和幂等键。短事务写入 Approval、WorkflowRun 与待派发 Job，重复请求读取既有结果。
4. Worker 认领 Job；费用门槛通过后提交服务商任务，保存 task_id 和输入快照。长任务通过状态查询或服务商可用的回调更新；回调去重，不能只相信浏览器进度。
5. 图片生成、声音与分镜可以在依赖满足时并行；配音完成后重算时码。未经核验的图生视频能力关闭时使用静态图片运动，或导入用户生成的片段。
6. 素材以内容哈希和对象 ID 入库，输出先落临时位置并校验，再原子性切换活动版本。时间线读取已校验素材，渲染预览并检查字幕、音轨和画幅。
7. 用户提交意见形成 ChangePlan。字幕大小、音量等只修改时间线或渲染；事实、旁白或形制变化标记关联镜头和下游时间线待复核，不覆盖已有成果。
8. 用户认可成片后创建 Export；下载只重打包，不重新调用媒体模型。交付包含来源清单与项目记录，不包含密钥和签名访问地址。

## 5 Job 与费用的故障一致性

数据库事务无法覆盖外部服务商网络调用，因此不能声称仅靠本地幂等记录就实现绝对只提交一次。首版按以下方式降低重复扣费风险。

- Job 生成稳定的幂等键，数据库设置唯一约束；服务商支持时同步传递该键。
- 认领状态写入 owner、lease_until 和 attempt；执行期间心跳续租，超时只重新认领本地任务，不立刻重发服务商请求。
- 提交前预留预计费用。提交后丢失响应时进入 unknown，继续占用费用预留，并优先按服务商 task_id、请求标识或幂等键核查。
- 服务商不能查到提交结果时，不自动重发付费任务；显示待核实并保留诊断摘要。
- 回调重复或乱序时按事件 ID 和可接受状态迁移处理；服务商不提供事件 ID 时用本地内容摘要去重。成功结果经文件校验才进入可使用状态。
- pause 只停止派发新任务。已提交任务根据服务商能力取消并继续核实费用，不把取消中当作已退款。
- SQLite 抢占和预算预留采用短写事务，外部调用在事务外执行，避免长期写锁。未来扩展 Worker 时重新验证租约和并发策略。

## 6 数据版本和迁移

产品版本与单条内容版本分离。产品 v1.0 表示交付和兼容边界；剧本 v2、镜头 v3、偏好第4版是用户内容历史，不要求每次生成都升级产品版本。

WorkflowRun 至少保存 product_version、db_schema_version、preference_version、skill_bundle_version、output_schema_version、model_config_version、timeline_schema_version 和输入资源校验值。模型服务可能更新，保存输入和配置不代表可以逐像素复现生成结果。

数据库迁移由独立 migration_id 管理；产品升级先备份数据库和资产索引，校验备份可读取，再运行迁移。迁移需判断旧项目是否可读、是否能继续旧任务以及导出协议是否兼容。不可逆迁移不能仅靠回退 Git 代码恢复数据库，必须保留迁移前备份和明确恢复方案。

JSON 导出带 schema_version。已有内容保留原来的 Skill、模型配置和输出 schema 快照；项目升级只在需要时创建新内容版本，不静默改变历史作品。

## 7 接口与事件边界

建议 API 资源为 projects、preferences、sources、scripts、workflow-runs、jobs、assets、feedback、exports。创建和审批使用幂等键及 expected_version；并发修改发现版本冲突时返回明确冲突信息，不默认最后写入覆盖。

异步接口先返回资源 ID 和受理状态；UI 通过可恢复轮询或事件流读取服务端状态。事件是通知，数据库记录才是恢复依据。文件读取检查项目权限，StorageKey 不直接当公开 URL；密钥由服务端配置注入。

模型输出优先使用结构化 schema；schema 合法、引用有效、费用允许、文件通过检查是不同关卡。拒绝、截断、空输出、缺失参考与服务商错误必须有可读状态，不能把一次 JSON 解析成功视为内容质量合格。

## 8 PRD 严格同步机制

PRD Markdown 是需求的唯一文本源，Word 是派生阅读版。需求追踪.json 按 F01–F42 保存原文摘要、页面、技术模块、验收映射与实现状态；当前全部为 design_only，不伪称已开发或验收通过。

VERSION 管理产品版本；技术架构、原型标签和发布清单读取同一版本。release_manifest.json 记录受控文件 SHA256 与生成源关系。同步检查验证版本、需求覆盖、文本摘要、页面路由、模块存在性、文件集合和校验值。

哈希只能发现文件是否变化，不能证明方案语义正确。每次迭代必须审阅需求是否改变、架构和页面是否受影响、费用及历史项目是否变化，并在变更日志记录实际结论。检查通过和人工影响评审共同构成发布门槛。

v1.0 设计基线建立后不覆盖同版本快照或重写 Git 标签；新行为使用 v1.1 等新版本，修正文案和不改变行为的修复使用 v1.0.1。未来新增需求编号从 F43 开始；历史编号只可废弃，不可重新解释成不同需求。

## 9 技术依据

以下为 2026年10月23日核对的官方资料，说明可选实现方式，不代表本账户已获接口权限或预算。具体版本和参数在实现时再次确认。

- OpenAI Responses API：文字、图像输入与工具交互的接口基础。[官方说明](https://developers.openai.com/api/reference/responses/overview)
- OpenAI 图片生成：说明图片 API 和 Responses 图片生成工具两种接入路径。默认图片能力经网关封装，不让用户逐镜选模型。[官方说明](https://developers.openai.com/api/docs/guides/image-generation)
- OpenAI 结构化输出：用于约束阶段输出结构；应用仍需处理拒绝、不完整结果与业务校验。[官方说明](https://developers.openai.com/api/docs/guides/structured-outputs)
- SQLite 的适用场景和并发边界支持单机初版的选型，未来多写者或多主机需求再评估客户端服务器数据库。[官方说明](https://sqlite.org/whentouse.html)
- FFmpeg 提供图像运动、拼接和音视频滤镜等基础；字幕能力取决于构建和相关依赖，需实际验证。[官方滤镜文档](https://ffmpeg.org/ffmpeg-filters.html)
- React 的组件与状态模型适用于拆分桌面页面和共享交互状态。[官方入门](https://react.dev/learn)
