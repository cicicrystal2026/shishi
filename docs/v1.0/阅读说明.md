# 拾史桌面端 V1 交付说明

## 先看什么

本轮统一冻结为 v1.0。开发者先读“拾史桌面端v1.0技术规格说明书.docx”，再结合“技术架构”中的图和说明、“contracts”中的接口及数据契约、“需求追踪.json”中的逐条映射。迭代操作见“版本管理.md”，当前基线校验命令为 `python tools/check_sync.py`。

1. 阅读“拾史桌面端V1_PRD.docx”，确认首版范围、页面职责、业务规则与验收条件。Markdown 是可编辑的同内容源稿。
2. 查看“页面总览.png”，快速比较八个页面和两个异常状态。
3. 用电脑浏览器打开“原型/index.html”，从左侧“新建作品”体验主流程。原型文件需和同目录的 style.css、prototype.js 一起保留。
4. 在“原型图”中逐张查看 1440px 宽的原始 PNG；页面较长时是整页截图，不裁掉底部操作。

## 页面对应关系

| 文件编号 | 页面 | 是否日常必经 |
| --- | --- | --- |
| 01 | 我的作品 | 项目入口 |
| 02 | 创作偏好 | 首次设置，之后按需修改 |
| 03 | 输入材料 | 是 |
| 04 | 确认故事 | 默认是，可在偏好中调整 |
| 05 | 自动制作 | 供查看进度，无需等待在页面 |
| 06 | 分镜与素材 | 否，需要精修时进入 |
| 07 | 审阅成片 | 是 |
| 08 | 导出作品 | 下载交付 |
| 09 | 预算暂停状态 | 仅异常时出现 |
| 10 | 来源与疑点状态 | 按需查看或处理关键疑点 |

## 原型可体验的交互

- 页面导航、偏好选择与本地保存。
- 文件选择后仅显示名称，不上传、不读取正文。
- 旁白直接编辑、来源弹窗与预算暂停弹窗。
- 分镜图片、片段和提示词标签切换，镜头详情与替换提示。
- 自然语言修改意见和快捷意见，修改记录示意。
- 导出说明与下一条创作入口。

这是产品设计交付，不是已接入 AI 的正式应用。器物是抽象视觉示意，示例旁白不包含真实文物史实。按钮不会生成图片、音频或视频，也没有真实 MP4 可下载。偏好中的预算只用于演示，不构成付费授权。

## 首版边界

电脑端 Web，先做旁白知识短片；GPT 默认处理资料、剧本、分镜和工具编排，分镜图通过经验证的图片能力生成。图片、配音与基础剪辑完成首条闭环；视频 API 通过接口和成本验证后启用，也可导入外部片段。文档没有承诺具体模型的接口、价格或生成耗时。

## 建议评审顺序

先确认 P02 默认偏好与 P04 故事方案是否足够省事，再看 P07 修改方式是否直观，最后确认哪些 P06 精修能力必须在首版提供。需求编号 F01–F42 可直接用于后续开发任务与验收追踪。
