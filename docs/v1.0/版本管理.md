# 拾史产品版本管理

当前产品版本 v1.0，基线标识 shishi-desktop-v1.0，交付阶段为设计基线。产品正式应用尚未实现。本目录单独建立 Git 仓库，只管理拾史，不管理父目录的其他项目。

## 1 哪份文件说了算

- VERSION：产品版本唯一入口。
- 拾史桌面端V1_PRD.md：需求唯一文本源；Word 是派生阅读版。
- 拾史桌面端v1.0技术规格说明书.md：开发技术契约说明；同名 Word 为派生阅读版，机器接口在 contracts 中。
- 需求追踪.json：逐条关联需求、页面、模块、验收与实现状态。
- 技术架构/architecture.json：架构图数据源；SVG、PNG、Mermaid 为生成物。
- 原型/index.html、style.css、prototype.js：交互原型源；单文件 HTML 和逐页图片为派生物。
- CHANGELOG.md：实际变更、兼容性、影响与验证记录。
- release_manifest.json：当前基线的受控文件哈希与派生关系。
- releases/v1.0：不可覆盖的交付快照和清单；Git 标签 v1.0 固定对应提交。

文件名中的 V1 是历史交付目录名，不是版本真源。后续版本沿用仓库，通过 VERSION、标签与 releases 目录定位，避免不断复制成“最终版2”“最新最终版”。

## 2 每次迭代的步骤

1. 建立 CHG 编号，记录问题、目标和验收方式，先写到 迭代记录.md。未实施想法只进待办，不提前宣称完成。
2. 判断是否改变行为。新能力或不破坏既有流程的行为扩展升到 v1.1 等版本；不改变行为的修复使用 v1.0.1；破坏数据或接口兼容性需要主版本升级及迁移方案。
3. 更新 VERSION、PRD、架构、原型、数据和验收中受影响部分。逐条刷新需求追踪的原文摘要；编号不可复用。未受影响部分在变更记录中注明理由。
4. 先生成 Word、架构图、单文件原型与截图，再检查视觉和交互。记录实际测试结果，不因设计完成而把实现状态改成 passed。
5. 生成新版本清单，运行 tools/check_sync.py。只更新哈希但未更新语义和派生物不算通过评审。清单工具不具备自动判断内容正确性的能力。
6. 检查数据库与旧项目兼容性，记录备份、迁移和恢复策略。当前设计基线无运行数据库，后续真实应用再执行迁移验收。
7. 创建不覆盖的 releases/vX.Y 快照，提交 Git 并创建同名标签。不得强制更新旧标签。Git 提交 ID 写入交付记录，旧 ZIP 的 SHA256 用于核对是否被修改。

## 3 同步检查的能力和限制

同步脚本验证版本一致、F 编号完整且唯一、逐条原文摘要一致、页面路由和模块存在、文件集合与 SHA256 一致、JSON 可读、PNG/SVG 图源一致性记录。新增文件漏进清单、需求原文改了但映射没改、派生物被替换，均应失败。

它不能判断“这张图是否表达了需求的全部语义”，也不能证明真实模型已接通或任务恢复一定正确。每次版本发布同时记录人工影响评审与实际实现验收，未来接入 CI 后也保留这一步。

## 4 命令

在本目录使用可用 Python 执行 `python tools/check_sync.py` 验证当前基线。执行 `python tools/build_prd.py` 和 `python tools/build_technical_spec.py` 从 Markdown 生成 Word；之后仍需完成 Word 渲染与逐页检查。执行 `python tools/render_architecture.py` 同时生成 SVG、PNG 与 Mermaid。原型更改后运行 `tools/render_prototype.cjs` 重导截图，再运行 `tools/build_delivery_assets.py` 更新单文件原型和总览。

`python tools/baseline.py manifest` 重新生成当前版本清单，仅允许在准备新基线时使用，不能用于掩盖未同步的改动；命令会显示这是清单更新，不是语义评审通过。`python tools/baseline.py snapshot` 在检查通过后建立版本 ZIP，目标目录存在即拒绝覆盖。

首次仓库使用 main 分支，标签 v1.0。后续建议 feature/CHG-编号-简述分支承载迭代，完成同步检查与评审再合并。当前没有配置远程仓库或云备份；本地 Git 和 ZIP 不能防范硬盘损坏，远程接入留待明确选择服务后执行。

## 5 产品与内容的版本区别

产品 v1.0、数据库 migration_id、输出 schema、Skill bundle、模型配置和用户每条作品的内容版本分别管理。每个 WorkflowRun 保存当时的版本快照。升级软件不能静默重写已有作品；回退软件也不能替代数据库恢复。
